# SportsMOT 运动门控饱和的机制研究 — 2026-11-21

问题：SportsMOT 的运动 gate 均值第 2–3 轮即饱和到 ~1（训练 0.999+，推理逐序列均值 0.9992–0.99999），
MOT20（~0.70）和 MOT17（~0.80）则保持内部值。本报告用三个数据集的真实 schema-3 分片回答：
这是数据机制决定的，还是监督/优化造成的？

复现：`.venv/bin/python tools/analyze_motion_gate_mechanism_20261121.py`
输出：`outputs/agentguard/experiments/chatgpt_mot_review_20261121/motion_gate_mechanism.json`

使用序列：
- SportsMOT：c003、c077、c001、HdiyOtliFiw_c004、gQNyhv8y0QY_c012（5 条，51,012 个有效事件）
- MOT17：02、04、11-FRCNN（67,379）
- MOT20：02、03（431,335）

## 1. 两个端点与"有害更新"的定义

- g=0：只用 KF 先验外推 t+1（不吸收当帧检测），g=1：用当帧检测更新 KF 后外推；两者都经过同一相机补偿。
- 有害更新（harmful）：`DIoU(g=1, GT_t+1) < DIoU(g=0, GT_t+1)`，即吸收检测反而更差。

## 2. 数据集特点（机制的第一层：有害更新的基础发生率）

| 指标 | SportsMOT | MOT17 | MOT20 |
|---|---:|---:|---:|
| 有效事件数 | 51,012 | 67,379 | 431,335 |
| **有害更新占比** | **14.4%** | 40.0% | 43.0% |
| DIoU(g=0) | 0.806 | 0.876 | 0.843 |
| DIoU(g=1) | **0.870** | 0.882 | 0.848 |
| 端点更新增益（DIoU g1−g0） | **+0.064** | +0.006 | +0.004 |
| 目标速度中位数（每帧位移 / 图像尺寸） | **0.00210** | 0.00057 | 0.00085 |
| 每帧样本数中位数（密度代理） | **12** | 41 | **107** |
| 检测分中位数 | **0.949** | 0.918 | 0.869 |

读数：SportsMOT 是"快、稀、检测准"——不更新的先验一帧后就过时（g=0 的 DIoU 比 MOT20 低 4 个点），
检测几乎总是更准；MOT20 是"慢、密、检测噪"——先验本来就不差，检测经常不可靠。二者共同决定
有害更新的基础发生率相差 3 倍（14% vs 43%）。这解释了为什么同一套平均 DIoU 损失在 SportsMOT 的
最优解在边界（g=1），在 MOT20 在内部。

## 3. 有害更新的条件结构（机制的第二层：信号在哪里）

有害率按特征分位数的变化：

| 特征 | SportsMOT | MOT17 | MOT20 |
|---|---|---|---|
| 检测分 最低→最高五分位 | **21.3% → 10.3%** | 43.9% → 37.3% | 44.2% → 40.3% |
| 速度 五分位（低→高） | 19.3 → 11.5 → **15.9%**（U 形） | 43.9% → 33.8% | 43.6% → 41.5% |
| 密度 低→高 | 13.5% → 15.5%（平） | ~40%（平） | 40.7% → 43.8% |
| 两端位移 小→大 | **23.3% → ~11%** | — | 44.9% → 41.8% |

关键模式：
- 检测分是最一致的方向：检测越差，更新越可能有害。
- SportsMOT 的速度呈 U 形：慢速时先验够用、更新反而引入噪声（19%）；中速更新最可靠；极快时检测本身
  容易错（16%）。
- 两端位移越小、有害率越高，但单次误判的代价也越小；位移大时更新基本正确且价值大。
- 所有单特征对"有害"的 AUC 只有 0.52–0.54，MOT20 更低（≈0.5）；信号是多变量、非线性的。

## 4. 门控输入里有没有可分信息（机制的第三层：信息 vs 优化）

用模型实际的运动门控输入（13 维 evidence + 3 维 competition）做逐事件分类探针，
按序列留出交叉验证：

| 数据 | 多数类基线 | Logistic AUC | GBM AUC（留出序列） |
|---|---:|---:|---:|
| SportsMOT（留一序列） | 85.6% | 0.575–0.661 | **0.631–0.753** |
| MOT17（留一序列） | 60.0% | 0.534–0.581 | 0.536–0.624 |
| MOT20（02↔03） | 56.6% | 0.543–0.554 | 0.595–0.603 |

- SportsMOT 的门控输入里**确实存在可利用信号**（GBM 留出 AUC 0.63–0.75，明显高于单特征）。
- 置换重要性最高的特征：框偏差 evidence ev0/ev2、KF 速度 ev4/ev6/ev7、检测分 ev10、competition comp1。
- 结论：SportsMOT 的饱和**不是纯信息不足**；平均一步 DIoU 回归 + sigmoid 饱和 + 少数类无配平，
  使模型没有利用这部分信号。

## 5. 收益上限（机制的第四层：值不值得修）

逐事件 oracle 门控（每事件取最优 g）相对恒定 g=1 的 DIoU 损失改善：

| 数据 | 恒定 g=1 损失 | oracle 损失 | 改善 |
|---|---:|---:|---:|
| SportsMOT | 0.1297 | 0.1220 | **5.96%** |
| MOT17 | 0.1177 | 0.1093 | 7.16% |
| MOT20 | 0.1523 | 0.1434 | 5.85% |

即：即使门控完美，也只能收回约 6–7% 的运动 DIoU 损失；对 HOTA 的影响尚未测量，预计更小。
这决定了机制级修复应当是"低成本的监督改动 + HOTA 验证"，而不是大改模型。

## 6. 机制结论

1. 运动门控本质是**检测可信度控制器**；SportsMOT 的检测又快又准又稀，更新几乎总有益，
   14.4% 的有害率使恒定 g=1 成为损失最优策略——门控"没做错事"，只是退化成了常数策略。
2. **信息不是主要瓶颈**：门控输入里 GBM 可达到 0.63–0.75 AUC，说明逐事件可区分性存在但弱、非线性。
3. 训练塌缩的直接原因是**目标函数形状 + 优化饱和**：平均一步 DIoU 的全局最优在边界 g=1
   （L(0.9)=0.1331 > L(1)=0.1275），少数类（14%）的单事件 DIoU 差很小（端点位移中位数仅为框尺寸的
   2–3%），加上 sigmoid 在 g≈1 处梯度约 1/2500，第 2–3 轮即锁定。
4. 理论上限有限：oracle 仅收回约 6% 的运动损失，HOTA 收益未知。

## 7. 对机制级修复的含义（未实施）

1. **先量化 HOTA 上限**（诊断，不改训练语义）：在 SportsMOT val 上强制 g=0/0.5/1 与逐事件 oracle，
   看 HOTA/AssA 的真实差距；若 oracle 增益 <0.1–0.2 pp，停止改造。
2. **改监督形式而不是调权重**：对每个事件监督"哪个端点更优"（软目标 sigmoid((DIoU1−DIoU0)/τ)），
   用 |DIoU1−DIoU0| 做 margin 加权并配平少数类，替代平均回归；这不改变 KF/EMA 语义。
3. **补端点可靠性特征**：两端位移/DIoU 差、KF 新息、检测分（已有）、协方差（evidence ev8/ev9）显式
   送入门控，而不是让门控从 13 维里自己挖。
4. 不建议用按数据集硬编码的损失倍率（如 ×8）作为最终方案——它是调参，且不解决边界解。
